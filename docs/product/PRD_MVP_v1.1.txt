1. 执行摘要与关键决策
RaaS MVP v1.0 的目标不是重做一套单一厂商“机器人 FMS”，而是建立统一的 Physical Service & Show Control Plane。首批产品覆盖擎朗、普渡的商业清洁、餐厅配送与酒店送物，以及宇树机器人在舞台、展会和品牌活动中的表演编排。平台对上接收清洁计划、配送订单、酒店服务请求和演出计划；对下通过厂商适配器与场馆 Edge 执行，并统一提供设备注册、任务/Cue 编排、状态监控、异常恢复和审计。
旧 MaaS 系统继续作为领域知识资产：订单生命周期、站点/区域、任务状态、实时通信、远程支持、权限与审计可迁入新模型；但 Legacy Zeus 接入不再是 v1.0 发布阻断项。首批工程资源优先保障 PUDU Open Platform、KEENON 合作接口与 Unitree SDK2 三条真实接入链路。
2027-02-12 目标发布 27 周日历基线
13–15 FTE 推荐团队 含机器人/表演工程
3 条真实适配路径 PUDU + KEENON + Unitree
2–3 个试点站点/场馆 8–25 台机器人
4 类首发场景 清洁/餐厅/酒店/表演

12 月先交付内部综合 Demo，2 月完成真实站点 Pilot；任一厂商接口资料或硬件未就绪时，不以模拟器冒充生产接入。

2.2 战略对齐
公司 2026 年机器人本土化战略要求掌握产品需求、系统架构、任务调度、设备管理、遥测、远程访问和客户门户。本次范围仍遵循“首期最多两条产品线”：第一条是共享室内移动与运营底座的商用服务机器人（清洁、餐饮、酒店），第二条是限定场馆、限定动作资产、有人值守的表演机器人。
聚焦：首个版本只做两条边界清晰的产品线，并锁定擎朗、普渡、宇树；不扩展到医疗、仓储重载、公共道路或任意机器人。
控制：租户、任务、演出计划、设备身份、日志、场地图、远程访问与客户 API 由 AMYGO 控制。
本地优先：配送/清洁的导航安全与表演动作执行均在机器人或场馆 Edge；云端只同步必要运营数据和高层命令。
可审计：设备身份、固件/动作资产版本、任务/Cue、远程访问、人工干预与异常恢复必须留痕。

3. 产品定义、目标与成功指标
3.1 产品定位
◆ 定位  面向商业服务机器人与表演机器人的多租户接入、任务/演出编排和运营平台，提供“业务 API + 厂商适配器 + 站点/场馆 Edge + 运营控制台”。它不是机器人操作系统，不替代厂商导航、运动控制或功能安全系统。

3.3 非目标（v1.0 明确不做）
不开发 SLAM、定位、避障、路径跟踪、清洁算法、机械臂运动规划或机器人安全 PLC 逻辑。
不从云端持续流式发送关节角、力矩或低层步态命令；宇树动作必须在场馆本地加载、校验和执行。
不承诺无人值守的人群中自由表演、跨场馆远程低层操控，也不把云端“停止”宣称为安全急停。
不在 v1.0 覆盖擎朗、普渡、宇树全部型号；只承诺经接口授权、实机 HIL 与 SAT 验证的 Model Profile。
不建设完整硬件商城、跨供应商交易市场、发票和复杂计费；v1.0 只记录站点、设备、任务和用量。
不建设完整 OTA 平台；v1.0 记录固件、适配器与动作资产版本，提供升级审计和回滚接口。
不把 Legacy Zeus、旧自动驾驶车辆、乘客 App 或公共道路 MaaS 能力作为首发必交。
不支持任意 BPMN 或在线生成未知舞蹈动作；仅使用版本化任务模板、有限条件和已审批动作资产。

4.3 代表性用户故事
作为清洁主管，我希望按楼层、区域和班次创建每日清洁计划，并看到中断、补水、回充、断点续清和完成报告。
作为餐厅运营员，我希望选择取餐口、桌台与回收点，确认装载后由合适机器人完成送餐或餐盘回收。
作为酒店前台，我希望创建客房送物任务，使用一次性取件码，并追踪电梯、到房、取物、超时和返回状态。
作为站点经理，我希望机器人断网后安全完成或暂停已接受任务，网络恢复后不重复开柜、送达或执行。
作为 Show Director，我希望把已批准动作、音乐 Cue 和机器人分组组合成节目单，彩排和预检通过后才能 Arm。
作为现场操作员，我希望在表演前检查电量、站位、通信、动作版本和安全区，并能在本地执行 Abort。
作为技术员，我希望统一查看 PUDU、KEENON、Unitree 的原始错误、标准错误、版本矩阵和最近操作。
作为集成工程师，我希望使用版本化 REST API、Webhook、PMS/POS/电梯连接器和 Adapter Profile，而不暴露厂商私有字段。
作为平台管理员，我希望所有远程指令、动作资产审批、身份变更和适配器凭证操作都能按人、时间和对象审计。
作为业务负责人，我希望分别看到配送 SLA、清洁完成率、表演成功率、机器人利用率、人工干预和支持成本。

商用机器人已经具备厂商导航、避障和本地安全能力；RaaS 仅通过正式接口下发高层任务并读取状态。
餐厅、酒店和清洁试点提供真实 SOP、地图/楼层、点位、班次与验收人员；酒店提供电梯/门禁/柜门测试环境。
宇树表演仅在受控舞台或展区、固定安全边界、现场操作员、物理急停和已审批动作资产条件下运行。
云账户、域名、证书、密钥、日志和动作资产仓库由 AMYGO 控制；Edge/Venue Controller 只需出站连接。
v1.0 支持中英双语界面；不处理支付数据、公共道路行驶数据或长期保存酒店客人身份信息。
Legacy MaaS 数据与 Zeus 硬件仅用于领域知识迁移和后续适配，不作为 v1.0 发布前提。

6.3 架构决策：模块化单体优先
MVP 阶段将租户、站点、机器人、任务、调度、告警和审计实现为一个代码仓中的独立模块，并通过领域事件/Outbox 解耦。部署上可分 API 与 Worker 两个进程，但共享同一逻辑数据库。只有当数据规模、发布节奏或团队边界真实出现压力时，再拆成独立服务。
选择
原因
约束
模块化单体
减少分布式事务、部署和观测成本；适合 13–15 FTE 与 27 周双轨交付周期
模块禁止直接跨边界访问表；通过 Application Service/事件交互
独立 Edge/Adapter
站点网络、协议依赖和生命周期与云端不同
必须可单独升级、回滚和离线运行
事件驱动但不过度中间件化
保留可扩展性和异步能力
v1.0 使用 Outbox + 轻量事件总线；避免引入多套队列

9.2 交互原则
原则
要求
状态先于装饰
机器人/任务/Show 卡片优先展示状态、新鲜度、错误、Profile/资产版本和当前执行。
动作可用性
按钮由角色、当前状态、Adapter/Profile 和本地安全门共同决定；不可用必须显示原因。
高风险分层
商用取消、酒店开柜、Show Arm/Start/Abort 使用不同确认级别、理由和审计。
本地安全可见
显示急停、遥控器、操作员、舞台区和 Preflight，但不允许云端清除本地安全状态。
实时但不抖动
商用位置分层刷新；Show 状态/Cue 高频但聚合显示，避免 UI 高频重绘。
多租户/场地清晰
页面始终显示当前租户、站点/场馆和环境；跨场地操作有明显提示。
中英一致
厂商状态、错误码、清洁/配送/Show 术语使用统一字典并保留原始值。

10. API、事件与适配器契约
10.1 API 设计原则
所有写 API 支持 `Idempotency-Key`；返回 `requestId/correlationId`。
资源 API 使用版本化路径，动作 API 使用语义明确的 `:pause/:resume/:cancel`。
错误使用统一 `code/message/details/retryable` 结构，不把厂商错误直接作为公共 API。
分页、过滤、排序和时间字段规范统一；所有时间使用 ISO 8601 UTC，站点时区仅用于显示。
Webhook 使用 HMAC 签名、指数退避、死信和可重放；Consumer 必须幂等。
Adapter Contract 通过 JSON Schema/Proto 定义，并建立兼容性与合同测试。

11.4 功能安全边界
!  不可越界
RaaS 不是安全控制系统。急停、碰撞检测、速度限制、安全区、制动和机械保护必须在机器人/本地控制器闭环中实现。云端“停止/取消”是任务命令，不得宣称等同安全认证急停。

原则
要求
本地优先
导航、清洁、运动、动作和安全停车由机器人/本地控制器负责；云异常不应导致危险动作。
物理急停独立
表演必须有可触达的物理急停/遥控器和现场操作员；云端 Abort 不能替代。
动作资产审批
只有签名、兼容、风险评级和实机彩排通过的资产可用于正式 Show。
场地安全门
观众边界、舞台区、站位、地面、障碍、照明、网络和撤离路线纳入 Preflight。
单主控制
同一机器人同一时刻只有一个商用任务或 Show 主控；厂商 App/遥控器冲突有明确优先级。
能力协商
控制台只展示 Adapter/Profile 验证动作，不能假定所有型号支持暂停、回充、开柜或动作 Cue。
变更管理
固件、动作、速度/力矩策略、安全区、设施接口变化必须审批、回归和现场复测。

13.4 回滚条件
出现命令重复、状态严重不一致或安全边界无法确认时，立即停止新平台下行命令。
RaaS 与 Legacy 对同一机器人主控租约冲突时，以安全停车和人工确认优先。
回滚只切换任务入口和命令主控，不回滚已经完成的数据迁移；通过 ID Mapping 保持审计连续。
切流后至少保留 2 周受控回滚窗口，之后再决定关闭旧实时链路。
